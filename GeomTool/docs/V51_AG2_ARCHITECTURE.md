# GeomTool v5.1 — AG2 原生前提提交与 DDAR 日志

## 改动范围

- `assets/ddar-compiler.js`：读取一次 Kernel 快照，按构造依赖生成所有有效点的数值坐标、内部见证点及几何形式前提。派生直线统一保存在 `lines[id] = [p,q]`，圆按构造类型产生等半径、共圆、直径圆直角等关系。
- `assets/app.js`、`index.html`、`assets/app.css`：在“尝试证明目标”和“尝试推理闭包”下方新增提交前提查看器，包含坐标、虚拟点用途、构造来源、形式谓词、直线见证点、圆结构与已知语义限制。运行后复用原样 `task.prepared.compiled`，而非重算出另一份所谓“已提交”的数据。可复制文本及下载日志。
- `vendor/alphageometry2/ddar.py`：对真实执行的 SSS、AA、SAS、带数值消歧 SSA、共线合并及圆发现添加可选的 DD 事件钩子。相似三角形事件记录两个三角形、判定类型、匹配前已证明的符号角/比例条件以及本次新增的相似性推论。
- `vendor/alphageometry2/elimination.py`：对成功插入高斯消元库的约束记录其添加前的精确符号线性表达式（AR）。官方算法本身并未被一个新的 JS 推理引擎替代。
- `vendor/alphageometry2/geomtool_v45_session.py`：运行开始时将全部坐标/形式假设/目标放在 JSONL 第一条，随后记录 DD、AR、原生 `check_pred` 已确认的查询。日志在 Pyodide 虚拟文件系统中按次重新生成；每条事件都写到磁盘文件，界面内仅保留最近一万条以控制内存。
- `assets/ddar-py.engine.worker.js`、`assets/ddar-py.worker.js`、`assets/ddar.js`：将日志内容通过现有会话 Worker 通道下载为 JSONL。

## 形式化对应策略

| 构造 | 提交给 AG2 的形式前提 |
| --- | --- |
| 两点直线 | 两个已知定义点作载体，不需额外公理 |
| 平行、垂直、三点平行/垂直线 | 原点/所过点与线上见证点组成线段，向其提交 `para`/`perp` |
| 中垂线 | 中点 `coll+cong`，经过中点的垂直线 |
| 角平分线、外角平分线 | 带有向线段的 `eqangle`；数值点确定内外分支 |
| 自由点 / 约束点 / 智能交点 | 自由点仅提交坐标；约束点按载体类型递归添加共线或共圆/等距条件 |
| 定圆心圆、定长圆、线段半径圆 | 已知圆心到已知圆上点的相等半径；定长圆加入内部半径点 |
| 三点外接圆 | 三个已知圆上点，必要时内部构造外心；共圆、半径关系 |
| 直径圆 | 直径中点为圆心，圆上点与直径两端满足 `perp` |
| 圆上切线、外点切线 | 优先圆心-切点半径垂直切线；无已知圆心时可尝试两弦的弦切角等式 |
| 中点、垂足、外心、垂心 | `coll`、`cong`、`perp` 的对应组合 |
| 内心 / 旁心 | 三顶点各自的角平分方向等式，数值几何负责内外分支 |
| 重心 | 三边中点（复用确切同一构造的已有中点）与三条中线共线及分割比 |
| 中心对称、轴对称 | 关于点的中点条件；关于轴的垂直平分关系及轴上定义点等距 |
| 平移、旋转、位似、等边 | 等长、平行、角常数、共线、比例常数，必须接受数值几何一致性检查 |

所有 `coll`、`para`、`perp`、`cong`、`eqangle`、`aconst`、`rconst` 在注入之前进行数值一致性检查；不满足时**跳过并报告限制**，不通过强行假定一个可疑关系来“完成证明”。这不意味着坐标成为公理：关系的逻辑来源仍必须是构造类型。

## 重要的数学边界

1. AG2 原生证明仅在给定实例的非退化、顺序、方向和交点分支上工作。`coll` 等普通正向谓词不能完整表达射线朝向、线段内部位置或两个圆的“第二交点”。这些条件继续由数值实例识别，不声称只凭正向关系就获得所有构型的有效证明。
2. 负位似的射线方向无法用 AG2 的模 180° 角与无向长度完整表达；编译器会明确提示限制。
3. `ElimCore` 新增日志只记录真正插入的方程，并**不保存全部高斯消元的父方程指针**。故 DD 日志可包含相似的前提与结论、AR 日志包含方程，但还不是每条推论都有严格父编号的完全形式证明 DAG。已有原生重放/前提消减证书保持使用。
4. 缺乏可靠前提或者带有退化的构造，可能无法产生全部预期形式关系。不能将可视化坐标检查代替一个形式证明。
5. 对象输入已不暴露「交点」「第二交点」独立构造工具及其控制台命令，智能点仍需用底层相交运算定位点；历史题库仍需要读取原有构造操作，因此 Kernel 中保留兼容解析方法，不作为可选工具或新命令。
