# GeomTool v3.4 — 基础构造蕴含系统与依赖图评分

本版本直接继承 v3.3，**仅**改造关系引擎内部构造事实、操作数匹配、带证据蕴含和评分。除产品版本号及为新逻辑加载一份 JS 外，不改画板、工具、对象管理、交互 UI、Kernel 或题库。

## 1. 内部构造事实（不是额外展示结果）

新增 `assets/relations/construction-logic.js`。每个事实带有：`node`（真正的 Kernel 节点）、`op`（构造操作）、`kind`（数学谓词）、`operand`（具体点/线/圆的 ID 或配对）及 `level`（定义/后果）。

基本覆盖 43 种 Kernel 构造，含中点、线上点、圆上点、两点直线、平行/垂直/中垂线、垂足、角平分线、三点圆、直径圆、重/外/内/旁/垂心、等边、平行四边形、轴/中心对称、旋转/位似、切线、交点、平移等。`circleRadius` 的半径事实含具体输入数值；线/圆的定义点事实在对应扫描类别未勾选时仍保留在内部。

**垂心 H=orthocenter(A,B,C)** 的最小蕴含图包含 11 条（不是 11 个独立几何定理）：

- 1 条：H 是 △ABC 垂心；
- 3 条：AH⊥BC、BH⊥AC、CH⊥AB；
- 1 条：A、B、C、H 四点垂心组；
- 3 条：A/B/C 分别也是其他三点的垂心；
- 3 条：四点两两分组给出的对边垂直（与上述高线可能属于同一个数学条件，内部为不同叙述，由蕴含图关联）。

这里明确区分**内部事实数量**与**最终独立展示条数**，绝不把每个蕴含都伪装为新发现。对不稳定、退化或未显式支持的结论不做数值伪造。

## 2. 真实操作数核对与合并

`provenance.js` 只有在检测结果的 `marks`/`metric` 和事实的具体点、线、圆完全对上时才附 `verifiedConsequences` 和 `constructionWitnesses`。

- 同一支撑线不同别名使用现有 `lineFamily` 统一；
- 一条长度连等如果同时含构造直接给出的 AB=AC 和另一个独立 AD，只将其标记为混合来源，不称整个关系直接来自构造；
- 四点垂心组可以解释一个**完整两支撑线**的垂直关系，但当一个垂直簇含更多独立线时不整组删除；
- 中点的共线和等长后果添加显式蕴含关联，为兼容原有语义检索和单独展示，仍保留原检索结果；
- 原有 `semantic.js`、去退化模块与旧蕴含规则不变，新增规则只处理能够一一核对的具体事实。

返回结果新增可选只读 `implicationGraph:{nodes,edges}`，节点区分构造 `C:`、内部事实 `F:`、检测结果 `R:`，边区分 `definition`、`consequence`、`witness`、`entails`；还返回 `constructionConsequences` 事实数。不会改变 UI。

## 3. 新评分公式

`scoreComponents` 仍主要是 `independentInformation`（上限 67）与 `nontriviality`（上限 33），并另外记录：

- `dependencyDepth`：参与结果的节点中，最长的 Kernel 依赖链长度。自由点深度为 0。
- `relationSparsity`：构造得到的点在**本次保留的关系列表**里的最大逆频率 `1/sqrt(1+n)`，避免高关系度热门点统治评分。
- `graphNovelty`：通过 `log2(depth+1)` 的饱和项 × （0.68 节点稀疏度 + 0.32 参与对象对的逆频率），衡量深度和局部关系独特性。
- `observedObjects`：该关系涉及的真实 Kernel 节点数，用于控制最小信息容量。

**只有深度且稀疏度够高才明显加分**，不能靠对象创建得晚或名称靠后获得奖励。直接构造定义（`origin==='construction'`）有独立信息量和非平凡程度的双重折扣；不对严格数值判定阈值或检测类别进行改动。

若图缺少构造元数据，深度视为 0，仅基于结果的已有分数和非平凡程度估值；评分不会尝试从最终坐标倒推出假依赖。

## 4. 最小构图审查和结论

新增 `tests/v34_construction_cases.test.cjs`，实际使用 Kernel 构造 **66 张不同参数/输入/操作组合的小图，覆盖 43 种构造操作**；每条内部关系的代表性几何约束通过坐标、点积、叉积、距离、圆心/半径等独立数值断言复核。结果：

- 122 条来自新操作的内部事实通过对应类型的几何核验；
- 75 个内部事实与扫描候选形成了可核实的直接来源匹配；
- 66 张图完整扫描，无关系分数越界、无对象构造失败；
- 不少「事实存在但无单独结果」是**有意**的：例如圆心与给定半径不是当前单独的发现类别，已有点在线上可能已归并到最大共线簇；这不应制造假的额外关系行。
- 测试输出 `docs/V34_MINIMAL_CASE_AUDIT.json` 汇总逐图事实数、见证数、扫描结果数，方便继续人工审查。

`tests/v34_scoring_implications.test.cjs` 单独核验深而稀疏的关系优先于浅而重复的关系，并验证构造定义的折扣、垂心图存在正确的 11 条内部事实。

## 5. 已知限制与测试范围

- 这是**具备操作数见证的局部蕴含图**，还不是完整欧氏几何形式证明器。它不会自动枚举所有能由作图演绎出的数学定理。
- 66 张小图的事实覆盖广，但不是对每个命令所有退化/任意输入配置的穷举证明；例如图形非常退化、点重合或无定义时仍要遵循 Kernel 的有效性判断。
- `construction` 信息来源必须是真正的依赖节点；用户从外部仅传点坐标时，不能归为作图事实。
- v3.3 归档中的备用扩展测试 `v33_relations.test.cjs` 原本在 `correspondence` 字段上与实际 `correspondences` API 不一致，该测试在未修改的 v3.3 基线上也失败，**不是** v3.4 所引入。v3.3 主测试与其余旧版本回归测试通过。此次依照要求未改动三角形对应机制。

在本版本没有进行大规模全库穷尽扫描或广泛浏览器回归；测试聚焦用户要求的基本构造、蕴含与评分。
