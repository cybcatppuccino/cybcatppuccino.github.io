# GeomTool v5 · Small UI / library-visualisation update

Based on GeomTool v4.7. The library database, GeomTool Kernel geometry constructors, native AG1/AG2 DDAR translation and inference, and numerical Pretty logic are unchanged.

## Four changes

1. **Relationship discovery re-enabled.** The earlier v4.5 CSS `display:none!important` hiding `#acc-relations` is removed. The complete existing scan-selection, category toggles, hidden-object and perturbation controls, filtering, sorting, paging, and canvas annotations are retained. Officially confirmed AG1/AG2 closure facts now appear alongside numeric candidates with the explicit **AG 已证明** badge. Formally confirmed facts are included even if the numeric discovery scanner did not enumerate them. A subset of structurally identical numeric discovery rows can also be badged. Unproved numeric candidates are never automatically promoted to proofs. AG1 internal point identifiers are displayed through the existing name-map when available.
2. **Initial layout.** `acc-objects` opens. `acc-complex`, `acc-relations`, `acc-proof`, and `acc-library` start collapsed. They remain independently expandable using the original accordion controls.
3. **Display-only library annotation layer.** New `assets/library-visuals.js` compiles the *source construction* into lightweight polygons, visible baseline segments and lines, circles, circumcircles, angle markers, perpendiculars, and foot segments. Sources include LL/LC/CC, circle/triangle/center constructors, angle bisectors, foot/altitude, parallel, midpoints, equilateral/square and other common drawing expressions. The marks track the current point coordinates when points are moved and the last loaded library entry is remembered with the local document. The layer does **not** call Kernel construction APIs, create or serialize geometry nodes, contribute to DDAR compiler input, or change theorem premises. Display marks referring to unavailable points are skipped. Coordinate-only AG2 entries retain their original points and visualise only directly mentioned predicate witnesses.
4. **Clickable proof steps.** Each recovered DDAR proof-chain step is now a button; selecting it overlays the relevant line/segment/point/angle witnesses using the same existing relation-overlay renderer. Where a backend has no recoverable full trace, its certified final conclusion is clickable instead; the UI does not fabricate intermediate proof steps. The overlay is independent of both the persistent graph and the relationship scanner.

## Scope / limits

No additional test suite or regression execution was requested or performed for v5. There is no claim that every theorem/predicate format can be rendered as a complete geometric annotation: unfamiliar forms fall back to resolvable points, and only genuinely returned DDAR conclusions are labeled proved. Visualization enhancements never change the geometric meaning of a source construction or the formal proof system.
