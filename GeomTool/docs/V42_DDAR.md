# GeomTool v4.2 — 纯 JavaScript DDAR、结论对齐与辅助构造

## 1. 安装 / 快速体验

**离线**：解压 `GeomToolv4.2.zip`，打开 `GeomToolv4.2/index.html`；也可直接打开独立发布的 `GeomToolv4.2-Standalone.html`。不需要 Python、Node、WASM、网络或模型 API。内建 2026 版 Chromium、Firefox、Safari 等支持标准 JavaScript 的现代浏览器即可。

1. 作图，或导入 `docs/sample-v42.geom.json`（上方「导入」）。示例含 `M` 是 `AB` 中点、`N` 是 `AC` 中点，以及辅助圆。
2. 右上角点击 **「⇄ 双栏推理」**：右侧「关系发掘」与「结论探知 · DDAR」在宽屏时并排对齐；小屏自动堆叠。运行**「扫描已勾选关系」**。
3. 「结论探知 · DDAR」点击 **「运行 DDAR 推理」**。关系列表内出现「✓ DDAR 已证」的项目，表示该条数值发现得到了本次规则集的独立推导支持。DDAR 的每条结论可展开规则与前提证据链。
4. 点击 **「✦ 推测辅助构造」**，浏览按已证结构和待证明关系排序的建议；选中可看到**不落盘的预览**，点「预测 DDAR 增益」则克隆构造图试算，再点「加入画板」提交。
5. 控制台支持 `ddar run` / `ddar aux` / `ddar stats` / `ddar export`。导出的证明负载包含完整 Kernel 图、形式结论、数值匹配、规则前提及辅助构造建议。

## 2. 与 v4.1 的关系

v4.1 的 **数值关系发掘** 保留。其目的在于寻找图形当前配置中成立、值得继续探索的关系；与之并行的新 **DDAR 推导系统** 只接受 Kernel 中已有的有效构造约束与已证明事实。二者是不同证据级别：

| 条目 | 含义 | 能否作为证明使用 |
|---|---|---|
| 关系发掘候选 | 坐标上经过数值精度检查成立 | **不能单独作为形式证明** |
| 「✓ DDAR 已证」 | 构造依赖 + 当前已实现的规则可独立推出 | **可以作为本系统已检查的形式结论** |
| 「尚未证明」 | DDAR 未能支持，或现有规则不完整 | **不是假命题** |
| 「暂不支持」 | 当前 DDAR 语义匹配器尚未覆盖该类 | **不代表几何事实为假** |
| 辅助构造建议 | 按结论结构预测潜在的作图方向 | **仅是假设；不等于推导** |

注意：本引擎是有明确已实现规则和上限的**高效 JS DDAR 子集**，不是 DeepMind AlphaGeometry 2 完整 DDAR 的逐规则移植，不包含一般线性规划 LP 全角度代数求解、任意多项式消元、自动寻证保证或大规模神经模型搜索。来源包中的 Python、Numba 与 SciPy 模块未被复制到网页，也不依赖 WebAssembly。

## 3. 核心架构

```
Kernel 有效构造图 ──────────┐
                           ├─→ 构造谓词种子 → DD 几何规则闭包 ←────┐
数值关系扫描 → 候选关系 ────┤                                     │
                           └─→ 数值候选 ↔ 已证谓词匹配            │
                                        │                          │
                                        ▼                          │
                         推导证据 / 待证明候选 / 焦点点集        │
                                        │                          │
                                  辅助构造候选排序               │
                                        │                          │
                       隔离 Kernel 克隆 + DDAR 二次试算 ─────────┘
                                        │
                                用户确认 → 构造入图
```

- `assets/ddar.js`：独立纯 JS 推理模块，Node 和浏览器均可加载。可扩展的事实索引 `(kind, sorted args)`、推导前提 ID、层级、规则 ID；默认 `maxFacts=8500`、`maxRounds=8`。线支撑用不相交集合并查集（UF），方向关系使用**带奇偶的 UF**，**线段长度乘法比例**使用带权 UF；已证相等和比例无需浮点坐标判断。
- `assets/auxiliary.js`：结构启发的多类别候选，首先关注出现在 DDAR 前提、等腰、共圆与未证明关系中的点；按图中证据参与度打分，去重并限制类别与候选总量。
- `assets/ddar.worker.js`：网页通过 Worker 执行推理，避免长推理阻塞 Canvas；当 `file://` 等环境阻止 Worker 时退回同一份纯 JS 实现。客户端的异步响应带修订号与运行令牌，以免旧结果覆盖新图。
- `assets/app.js`：双栏状态和界面、与旧 Radar 的匹配、推理详情、隔离试算、创建辅助构造与撤销链。

### 目前实现的推理规则（非穷举）

| 规则主题 | 核心处理 |
|---|---|
| 构造约束导入 | 线/圆上的点、两载体交点、中点、垂足、平行/垂线、三点外接圆、直径圆、等边点、外心、垂心、重心、中心对称、平行四边形等 |
| 共线 / 支撑线 | 两点确定支撑线、共线传递、已知线上的点重聚合；排除几何重合导致的不确定支撑线 |
| 方向与角 | 平行与垂直奇偶传播、两直线同时垂直第三条线推平行、有向圆周角（mod 180°）、泰勒斯定理及逆定理 |
| 长度与比例（AR） | 同圆半径相等、线段转移半径、等边三角形等长、等腰、已证中点的 2:1 比例、中位线定理及 2:1 比例、重心 2:1 比例、带权比值传递 |
| 点与圆 | 同一圆上的四点共圆、由同圆心等距反推点在圆上、外接圆推出圆周角 |
| 反向规则 | 共线 + 两端等长 ⇒ 中点；两点同时到 A/B 等距 ⇒ 两点连线垂直 AB |

仅已确认构造有效的图节点参与推理。浮点坐标用来过滤重合、零方向及无意义的退化情形，而**不用于生成等长、垂直、平行等证明事实**。具体推理证据链可在 DDAR 列表中点击展开。相对于任意形式证明器，这仍是工程级规则实现，复杂图形的严格性需要独立数学复核。

### 与 v4.1 数值关系的对应

优先支持 `parallel`、`perpendicular`、`collinear`、`concyclic`、`pointOnLine`、`pointOnCircle`、`midpoint`、纯线段 `distanceRatio`、`equilateral`、直角 `fixedAngle`、`diameter` 及 `perpFoot`。当 v4.1 对某一大类采用压缩簇时，必须证成**簇的每一项**，而非只匹配其中一对。含虚拟圆半径、点到线距离等非线段度量的比值仍明确为「尚未证明」。目前不支持的关系类别返回 `unsupported`。

## 4. 辅助构造探测

当前候选包含：

- **结论引导中点**：将中点/中位线、等腰对称轴、平行与线段比引入同一证据网；只选高相关点对，避免全图笛卡尔穷举。
- **等腰点的垂足与中垂线**：从已经推得的 `VA=VB` 识别等腰底边，推测足点、中点、中垂线。
- **辅助圆**：以已证等腰顶点为圆心作过底边点的圆；对结论中相关三点建外接圆；作直径圆用于探索泰勒斯结构。
- **已有载体的交点**：正确处理直线/线段/射线的交点范围及线圆、圆圆两交点的分支编号，过滤已命名交点。
- **自动补线交点**：若两条合适的隐含 AB 与 CD 尚未作图，可建议「补作 AB ∩ CD」，内部顺序创建两条辅助直线及交点。用户提交时以一次 Kernel 导入原子写入，使撤销只需一次操作。
- **平行/垂线**：将结论高相关点与已有支撑线连接，引入直角或可进一步运用的平行结构。

建议的排名是启发式**尝试优先级**，并非证明难度、最短证明长度或成功率的精确估计。「预测 DDAR 增益」只对单个候选隔离求一次当前规则闭包，显示新增事实数及与现有关系相符的新证明数；它不会自动修改原图。

## 5. 性能与边界

1. 默认推理最大 **8500 条事实 / 8 轮**；隔离试算是 **5500 条 / 7 轮**。截断会显示提示，属于未穷尽规则，不是推理失败。为了避免共圆组合爆炸，一次只枚举同圆中至多前 14 个命名点的四元组；完整共圆候选的匹配仍能检查全体受约束圆上点。
2. 通过语义索引和 UF 使常见平行/垂直/比例传递避免一般性的角方程全矩阵求解。极端高度对称配置可能显著增大结论集合，执行耗时取决于浏览器与数据规模。
3. 如果两个不同名字处于同一坐标位置，不能把它们作为定义一条**唯一**直线的两端；退化载体不参与方向或共线支撑等价类推理。
4. 理论上的几何符号演绎，与数值坐标看起来成立是两个层次。移动自由点后，旧 DDAR 结果立即作废；重新扫描/运行。
5. `DDAR` 模块本身可以独立在 Node 运行：`const r = require('./assets/ddar.js').infer(kernel.snapshot())`。`GeomAuxiliary.suggest(snapshot, r, entries)` 输出推荐；`GeomAuxiliary.execute(kernel,candidate)` 真正执行候选（复合操作在 UI 内部使用隔离克隆并一次提交）。
